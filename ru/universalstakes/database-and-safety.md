# База данных и безопасность

> **Перед обновлением плагина:** остановите сервер и **создайте резервную копию базы данных**. Эта одна привычка
> предотвращает большинство проблем с потерей данных.

---

## SQLite — значение по умолчанию

SQLite не требует отдельного сервера базы данных. Его файл — `plugins/UniversalStakes/data/data.db`. Используйте это
для обычного сервера Minecraft.

- **Не** открывайте и редактируйте `data.db` во время работы сервера.
- Соответствующим ключом `config.yml` является `database.sqliteFile` (по умолчанию `data/data.db`); MySQL и пул
  настройки игнорируются.

---

## MySQL — внешнее хранилище

Используйте MySQL, если у вас уже есть сервер базы данных или вам нужны данные за пределами игрового сервера.
```yaml
database:
  type: mysql
  host: localhost
  port: 3306
  name: universalstakes
  user: universalstakes
  password: "your-password"
  poolSize: 10
  sslMode: VERIFY_IDENTITY
  trustCertificateKeyStoreUrl: "file:/absolute/path/to/mysql-client-truststore.p12"
  trustCertificateKeyStorePassword: "change-me"
  allowPublicKeyRetrieval: false
```
> MySQL **не** поддерживает сеть с несколькими серверами. **Ровно один** активный экземпляр UniversalStakes
>может использовать базу данных. Не размещайте несколько серверов Paper в одной и той же схеме — жизненном цикле и финансовой
> Координация носит локальный процесс.

### Безопасная настройка MySQL

- `VERIFY_IDENTITY` — безопасный вариант по умолчанию: он шифрует соединение, проверяет цепочку сертификатов,
  и проверяет соответствие сертификата `host`. Поместите центр сертификации базы данных в выделенное хранилище доверенных сертификатов PKCS#12/JKS.
  и используйте его абсолютный URL-адрес `file:`.
- **Не** устанавливайте `allowPublicKeyRetrieval: true` вместо TLS. `REQUIRED` и `VERIFY_CA`
  ослабить проверку имени хоста; `PREFERRED`/`DISABLED` допускает использование открытого текста и не должен использоваться для
  удаленная база данных.
- Создайте **выделенного пользователя базы данных с наименьшими привилегиями** вместо `root`. Плагин создает свой собственный
  таблицы и индексы. Ограничьте учетную запись и сетевой ACL хостом Minecraft — ожидается вознаграждение
  записи могут содержать команды, которые позже запускаются в консоли.
- Пароль базы данных и пароль хранилища доверенных сертификатов представляют собой обычный текст в формате `config.yml`. Ограничить доступ к файлам
  в учетную запись сервера и не допускайте попадания этого файла в общие резервные копии/журналы.

Изменение настроек базы данных требует **перезапуска** (пул создается только при запуске).

## Обеспечьте безопасность сервера

- Проверьте команды вознаграждения на тестовом сервере, прежде чем включать ставку для реальных игроков.
- Никогда не предоставляйте игрокам или ненадежным модераторам доступ на запись к файлам плагинов.
- Создайте резервную копию базы данных перед изменением типа базы данных или редактированием большого количества ставок.
- Не останавливайте намеренно сервер во время получения наград.
- Сохраняйте каждый идентификатор `currencies.yml` и его команды отдачи/возврата **без изменений**, пока ставка, использующая его,
  невостребованный возврат валюты. В ожидании возврата сохраняется идентификатор валюты, а не историческая копия ее.
  шаблон команды — его изменение/удаление и перезапуск могут отправить старый возврат через новый
  командовать или сделать невозможным требование. Подождите, пока эти награды не будут решены.

## Автоматические результаты (команда сверки не требуется)

Плагин никогда не требует ручной команды согласования. Каждый завершенный раунд можно проверить с помощью
`/stakes admin logs <stake-id>`; в меню отображаются **неизменяемые** события — игрок, сумма, валюта,
Идентификатор операции, результат и любая ошибка. Только раунды с событиями, записанными после установки этой функции.
появиться; исторические результаты родов не реконструируются.

| Результат | Когда это произойдет | Что делать |
| --- | --- | --- |
| `PENDING` | Награда ожидает получения, или подтвержденная временная ошибка вернула ее обратно. | Игрок снова нажимает кнопку `/stakes rewards`. |
| `BLOCKED` | Команда вознаграждения была неоднозначной (возможно, частично сработала), поэтому она не воспроизводится автоматически. | Просмотрите `/stakes admin logs <stake>` и устраните проблему вручную. |
| `BLOCKED` (после сбоя) | Аренда `CLAIMING` старше 5 минут во время сбоя. Перемещено на `BLOCKED` при запуске/каждые 60 секунд. | То же — просмотр и решение вручную; его нельзя требовать снова. |
| `UNCONFIRMED` (депозит) | Вывод внешней валюты во время депозита не удалось подтвердить. | Депозит аннулируется **без** зачисления ставки. Повторная попытка не повторилась. Проверьте провайдера. |
| `PAYOUT_FAILED` (вывод) | При выводе средств по щелчку правой кнопкой мыши реестр уменьшился, но выплата игроку не состоялась. | Компенсируйте игроку вручную. Взнос уже удален — **не** говорите им, чтобы они повторили вывод средств. |

`auditLog.retentionDays: 0` сохраняет события аудита навсегда. Положительное значение удаляет только просроченный аудит.
события; он никогда не удаляет финансовые или круглые записи.

## Ограничения безопасности (для всего плагина)

Эти границы предотвращают переполнение целых чисел/точностей и неограниченную полезную нагрузку базы данных. Проверка отклонена
значения, которые их превышают — уменьшайте суммы, списки команд или метаданные элементов вместо того, чтобы обходить их,
и никогда не редактируйте слишком большие значения непосредственно в базе данных.

| Лимит | Значение |
| --- | --- |
| Любая финансовая сумма (инвестиция, вывод, итог, ввод возврата) | максимум `9,007,199,254,740,991` |
| Сериализованная полезная нагрузка ожидающего вознаграждения | максимум `60,000` UTF-8 байт |
| Закодированный бюджет команд вознаграждения на блок вознаграждения | `12,000` байт (по одной строке, без зарезервированного символа U+0001) |
| Импортированный снимок пользовательского элемента | самое большее `32 KiB` двоичный |
