# Как это работает

На этой странице простым языком объясняется весь плагин: где находятся файлы, что такое раунд и
что происходит шаг за шагом, когда игроки вносят депозит, когда заканчивается таймер и когда они получают награды.
Вам не нужно читать исходный код — здесь все имеет значение для запуска плагина.

---

## Макет файла

После первого запуска ваша папка `plugins/UniversalStakes/` выглядит так:
```text
plugins/UniversalStakes/
├── config.yml              ← global settings (database, commands, language, safety)
├── currencies.yml          ← registry for external PlaceholderAPI currencies (optional)
├── data/
│   └── data.db             ← the SQLite database (default storage)
├── imported-items/         ← snapshots of custom items (made by /stakes admin importitem)
└── language/
    └── english/            ← the active language pack (one folder per language)
        ├── messages.yml    ← chat messages sent by the plugin
        ├── menus/
        │   ├── stakes-main.yml
        │   ├── stakes-menu.yml
        │   ├── deposit-menu.yml
        │   ├── stakes-history.yml
        │   ├── stakes-rewards.yml
        │   ├── stakes-admin-logs.yml
        │   └── stakes-admin-log-events.yml
        └── stakes/
            ├── coinfever.yml       ← one file per event
            └── diamondrush.yml
```
### Что делает каждый файл

| Файл/папка | Что он контролирует |
| --- | --- |
| `config.yml` | Тип базы данных, имена команд, выбор языка, обработка банов, сохранение аудита, отладка. См. [Конфигурация](Configuration.md). |
| `currencies.yml` | Определения валют `PLACEHOLDER` (экономики без моста Хранилища). Требуется только в том случае, если вы используете этот тип. См. [Валюты](Currencies.md). |
| `data/data.db` | База данных SQLite. Не открывайте и не редактируйте его во время работы сервера. |
| `imported-items/*.item` | Снимки пользовательских элементов, используемые источниками вклада `CUSTOM_ITEM`. |
| `language/<locale>/messages.yml` | Все сообщения чата плагина. См. [Сообщения и заполнители](Messages-and-Placeholders.md). |
| `language/<locale>/menus/*.yml` | Игроки видят меню инвентаря. См. [Меню](Menus.md). |
| `language/<locale>/stakes/*.yml` | Один файл на событие. Здесь вы проводите большую часть своего времени. См. [Настройки ставок](Stake-Settings.md). |

> Плагин поставляется с **19 языковыми пакетами**. При первом запуске он извлекает их все в
> `language/`. Вы можете удалить те, которые не используете — они никогда не воссоздаются автоматически. Выбрать
> один с `locale:` в `config.yml` (например, `english`).

### Два стиля именования, которые следует запомнить

- **`config.yml`** использует ключи `camelCase`: `sqliteFile`, `poolSize`, `promptTimeoutSeconds`.
- **Ставьте файлы и `currencies.yml`** используйте ключи `kebab-case`: `withdrawals-enabled`, `raw-placeholder`.

И то и другое нормально — плагин специально их так читает. Просто скопируйте написание из этой вики или
из файлов примеров.

## Из чего сделан «кол»

Каждое событие представляет собой один файл `.yml` с одинаковыми строительными блоками:
```text
stake file
├── display        how the event looks in the main menu (icon, name, lore)
├── alias          the short command, e.g. /diamonds
├── permission     optional: who can see and join this event
├── withdrawals    can players take resources back during a round?
├── messages       what is broadcast when the round starts, runs, and ends
├── contributions  the resources players can deposit (currency + points + limits)
├── time           round length, cooldown, auto-restart
└── prizes         top-place prizes + consolation tiers + refunds
```
Вам нужно заполнить только те блоки, которые вас интересуют. Полная ссылка на поле за полем находится в
[Настройки ставки](Stake-Settings.md).

## Как работают баллы

Очки — это результат в таблице лидеров. Каждый источник вклада имеет значение `points`. Когда игрок
вносит сумму, они зарабатывают **`amount × points`**.
```text
Example: a "diamonds" source with points: 5
  Player deposits 10 diamonds  →  10 × 5 = 50 points
  Player deposits 3 more       →  total 13 diamonds = 65 points
```
Если у ставки несколько источников, очки от каждого просто суммируются. **Источники никогда
конвертируются друг в друга** — 10 алмазов и 20 морковок остаются отдельными, они просто складываются в одно и то же
оценка. `points` должно быть положительным целым числом (без десятичных знаков).

## Жизненный цикл раунда (события)

**Раунд** — это однократный розыгрыш ставки. За кулисами каждый раунд проходит через несколько состояний.
Вы не контролируете эти состояния напрямую, но знание их помогает вам понять правила перезагрузки и
сообщения об ошибках.
```text
              (auto-restart or /stakes admin start)
                            │
                            ▼
        ┌──── ACTIVE ───────────────────────┐
        │  Players deposit and withdraw.    │
        │  Reminders broadcast on interval. │
        │  Timer counts down.               │
        └──────────────┬───────────────────┘
                       │ timer ends  OR  /stakes admin stop
                       ▼
                  CLOSING  ← wait for any in-flight deposits to settle
                       │
                       ▼
                FINALIZING  ← calculate results, store pending rewards
                       │
                       ▼
                   ENDED  ← broadcast winners, prizes become claimable
                       │
                       │  (if auto-restart: true)
                       │  wait restart-delay, then a new ACTIVE round starts
                       ▼
                   next round…
```
### Что происходит на каждом этапе

- **Раунд начинается** → плагин записывает событие аудита `ROUND_STARTED` и транслирует его
  `messages.started` каждому онлайн-игроку, который может получить доступ к событию.
- **Пока активен** → игроки вносят/снимают средства. Каждый `reminder.interval` (например `5m`)
  `reminder.message` транслируется онлайн-игрокам, имеющим доступ к событию.
- **Раунд заканчивается** (таймер или остановка администратора) → раунд переходит через `CLOSING` → `FINALIZING` → `ENDED`.
При финализации рассчитывается рейтинг, создаются **ожидающие награды**, а затем транслируется.
  `messages.stopped` (с заполнителями для победителей) соответствующим онлайн-игрокам.
- **После его завершения** → если `auto-restart: true`, плагин ждет `restart-delay` и запускает новый
  округлить автоматически. Если сервер был отключен в момент истечения этой задержки, новый раунд начинается в
  следующий запуск. Раунд, который был **активен на момент остановки сервера, возобновляется** при перезапуске, поэтому депозиты
  никогда не теряются молча.

### Состояние одной ошибки

Если база данных когда-либо содержит статус раунда, который плагин не распознает, этот раунд переходит в
**`ERROR`** и не закрывается: **депозиты не принимаются**, пока администратор не устранит проблему.
строка базы данных. Это сделано намеренно — он никогда молча не открывает сломанный раунд. Вы увидите ясное
ошибка консоли в названии ставки и раунда.

## Что происходит, когда игрок вносит депозит

1. Игрок открывает меню депозита и щелкает левой кнопкой мыши по источнику вклада.
2. Плагин спрашивает в чате: *введите сумму для инвестирования, или отмените*.
3. Игрок вводит целое число.
4. Плагин проверяет: активен ли раунд? Является ли сумма внутри `min-invest`, `max-invest` и
   `daily-limit`? Действительно ли у игрока есть столько ресурсов?
5. Если все в порядке, ресурс забирается у игрока и очки добавляются в
   таблица лидеров.
6. Для внешних валют (PlaceholderAPI) плагин запускает настроенный вами `take-command`, а затем
   **проверяет, что баланс изменился именно на эту сумму**. Если он не может подтвердить изменение,
   депозит аннулируется **без** начисления баллов и в журнале аудита появляется запись `UNCONFIRMED`.

**Щелчок правой кнопкой мыши** запускает вывод средств (только если `withdrawals-enabled: true` и раунд активен).
Ресурс возвращается игроку **немедленно и напрямую** — он никогда не проходит
`/stakes rewards`. Совпадающие точки удаляются с доски.

---

## Что происходит, когда раунд заканчивается и награды забираются

1. После завершения плагин ранжирует каждого участника по баллам.
2. Призы за первые места (`prizes.top`) создаются как **ожидаемые награды** для игроков с рейтингом.
3. Утешительные уровни (`prizes.others`) передаются следующим игрокам, а также всем настроенным
   `refund-percent` своего депозита.
4. Каждый затронутый игрок получает сообщение в чате, указывающее на `/stakes rewards`.
5. Игрок открывает `/stakes rewards`, нажимает на награду (или **Требовать все**) и настроенную награду.
   команды запускаются **как консоль сервера**.

> Команды вознаграждения выполняются с правами **консоли**. Вот почему только доверенные сотрудники должны редактировать ставку.
> файлы. См. [База данных и безопасность](Database-and-Safety.md).

### Что делать, если доставка не удалась?

- **Временная** ошибка возвращает награду `PENDING`, поэтому игрок может просто нажать еще раз.
- **неоднозначный** сбой (возможно, команда сработала частично) отмечает награду **`BLOCKED`**, поэтому
  никогда не переигрывается автоматически — переигрывание может дать приз дважды. Админ просматривает это в
  `/stakes admin logs <stake>` и разрешает его вручную.
- Если сервер **зависает в середине заявки**, застрявшая аренда `CLAIMING` старше 5 минут переносится на
  `BLOCKED` при запуске (и каждые 60 секунд). Он остается видимым для администраторов, но не может быть востребован снова.
