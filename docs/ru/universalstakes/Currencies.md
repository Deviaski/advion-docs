# Валюты

Источник вклада занимает блок `currency`. Существует **четыре типа**. Выберите тот, который соответствует
какой депозит должны внести игроки.
```yaml
contributions:
  diamonds:
    currency:
      type: ITEM          # or VAULT / PLACEHOLDER / CUSTOM_ITEM
      material: DIAMOND   # depends on type
    points: 5
```
## Четыре типа с первого взгляда

| `type` | Какие игроки вносят депозит | Требуется дополнительная настройка |
| --- | --- | --- |
| `ITEM` | Обычный предмет Minecraft (бриллианты, изумруды…). | Только `material:`. |
| `VAULT` | Виртуальные деньги из плагина вашей экономики. | Установите Vault + плагин экономики. |
| `PLACEHOLDER` | Целочисленный баланс из экономики без моста Хранилища. | PlaceholderAPI + запись `currencies.yml`. |
| `CUSTOM_ITEM` | Импортированный снимок элемента (ключи, именованные элементы, NBT, данные пользовательской модели). | `/stakes admin importitem`. |

---

## `ITEM` — обычный предмет Minecraft.

Самый простой тип. Игроки кладут ванильный материал из своего инвентаря.
```yaml
currency:
  type: ITEM
  material: DIAMOND
```
`material:` — любое допустимое имя материала Bukkit (заглавные буквы, например `DIAMOND`, `EMERALD`, `CARROT`).

---

## `VAULT` — виртуальные деньги

Используйте это, когда игрокам нужно внести деньги на сервер вместо предметов.
```yaml
currency:
  type: VAULT
```
Требования:

1. Установите **Vault** и плагин экономики, совместимый с Vault. Перезапустите сервер.
2. Ищем консольное сообщение, подтверждающее подключение экономики.
3. Как обычно, дайте игрокам разрешение на депозит.

Если экономика не найдена, источники `VAULT` не могут принимать депозиты (источники предметов в той же ставке по-прежнему
работа). UniversalStakes **не** сама создает деньги.

---

## `PLACEHOLDER` — экономика без моста Хранилища

Для стран, которые предоставляют баланс через PlaceholderAPI, но не имеют перехватчика Vault (PlayerPoints,
Отличная экономика, CoinsEngine,…). Ставка относится к валюте по ее **ID** и фактическому значению.
определение находится в `currencies.yml`.
```yaml
# in the stake file
contributions:
  gems:
    currency:
      type: PLACEHOLDER
      id: gems
    points: 1
```

```yaml
# in plugins/UniversalStakes/currencies.yml
currencies:
  gems:
    display-name: "Gems"
    symbol: ""
    raw-placeholder: "%coinsengine_balance_gems%"
    give-command: "ce give %player% gems %amount%"
    take-command: "ce take %player% gems %amount%"
    works-offline: false
    balance-check-after: true
    balance-check-delay-ticks: 5
```
### поля `currencies.yml`

| Поле | Значение |
| --- | --- |
| `display-name` | Обязательное имя, используемое для проверки. |
| `symbol` | Необязательные метаданные (не отображаются автоматически в текущих меню). |
| `raw-placeholder` | Должен возвращать **только цифры** — без символов, запятых, десятичных знаков и цветовых кодов. |
| `give-command` / `take-command` | Запускайте от имени **консоли**. Должен содержать `%player%` и `%amount%`. Ведущий `/` не является обязательным. |
| `works-offline` | Может ли провайдер читать/работать на автономном плеере? Обычные депозиты запускаются онлайн-игроками. |
| `balance-check-after` | После команды перечитайте баланс и требуйте его изменения ровно на эту сумму. |
| `balance-check-delay-ticks` | Подождите столько тактов перед проверкой баланса после команды (для экономик с асинхронным обновлением). |

### Как подтверждается депозит PLACEHOLDER

1. Считайте баланс игрока с `raw-placeholder`.
2. Запустите `take-command` в качестве консоли.
3. Подождите `balance-check-delay-ticks`, затем снова прочитайте баланс.
4. Баланс должен уменьшиться **точно** на запрошенную целочисленную сумму.
5. В случае невозможности подтверждения депозит **аннулируется без начисления баллов** и журнал аудита
   записи `UNCONFIRMED`. Он никогда не повторяется автоматически.

> Сгенерированные `currencies.yml` отправляют **шаблоны** PlayerPoints и ExcellentEconomy. Проверьте
> Идентификатор валюты, псевдоним команды и заполнитель в конфигурации вашей экономики перед их использованием.

> Никогда не редактируйте и не удаляйте существующую запись `currencies.yml`, пока ставка, использующая ее, все еще невостребована.
> возвраты — в ожидании возврата хранится идентификатор, а не копия старой команды. Разрешения на перезагрузку **добавление**
> только записи; изменение/удаление требует перезагрузки и небезопасно, пока эти награды не будут решены.

## `CUSTOM_ITEM` — снимки импортированных элементов
Для ключей, переименованных элементов, элементов NBT или элементов с данными пользовательской модели.

### Шаг 1 — импортируйте предмет

Возьмите образец в **основную руку** и запустите:
```text
/stakes admin importitem <item-id>
```
Элемент сохраняется глобально как `plugins/UniversalStakes/imported-items/<item-id>.item`. Идентификатор элемента
глобальный и может быть повторно использован несколькими ставками.

### Шаг 2 — используйте его в ставке

**Идентификатор источника вклада должен совпадать с идентификатором импортированного элемента**. **Не** добавляйте `currency.id` или
Поле `item:` — при поиске пользовательского элемента всегда используется идентификатор источника.
```yaml
contributions:
  magic_key:              # this ID must match the imported item ID
    currency:
      type: CUSTOM_ITEM
      match-mode: SIMILAR
    points: 10
```
### `match-mode` — как сопоставляются стеки

| Режим | Что он проверяет |
| --- | --- |
| `SIMILAR` | Нормальный, щадящий выбор. Соответствует типу элемента и ключевым данным элемента. |
| `EXACT` | Требуется полное и точное совпадение всего стека. |
| `CUSTOM_MODEL_DATA` | Проверяется только материал **и** данные пользовательской модели. |

Импорт нового снимка (или повторный импорт) вступает в силу после **перезапуска**.

## Смешивание источников

Ставка может иметь несколько источников вкладов разных типов. Их очки просто складываются;
ресурсы никогда не конвертируются друг в друга.
```yaml
contributions:
  diamonds:
    currency: { type: ITEM, material: DIAMOND }
    points: 5
  coins:
    currency: { type: VAULT }
    points: 1
```
10 бриллиантов (×5 = 50) + 1000 монет (×1 = 1000) = 1050 общих очков.
