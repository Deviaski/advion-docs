# Stake Settings Reference

> **Use this page when:** You already have a stake file and want to understand one of its settings. For a copy-paste starter file, use [Create Your First Stake](First-Stake.md).

The stake ID is its file name without `.yml`. Use simple lowercase names such as `weekly-diamonds.yml`.

## Display block

`display.name` is the title of the stake card in the GUI. `display.display-name` is the human-readable stake name used in messages, history, rewards, and the PlaceholderAPI; when omitted it falls back to `display.name`. `display.lore` is the card description. `display.material` is a Minecraft material such as `DIAMOND`, `PAPER`, or `EMERALD`. `model-data` is for resource packs; leave it as `0` when you do not use one.

Text supports MiniMessage formatting, for example `<red>Red text` and `<gold>Gold text`.

Language messages use built-in placeholders in braces, for example `{prefix}`, `{stake}`, and `{permission}`.
MiniMessage formatting tags remain in angle brackets.

## Currency block

| `type` | Required setting | What players deposit |
| --- | --- | --- |
| `ITEM` | `material: DIAMOND` | A normal Minecraft item. |
| `VAULT` | Nothing else | Money from your Vault economy. |
| `CUSTOM_ITEM` | `item: item_id` | An imported item snapshot. |

For `CUSTOM_ITEM`, hold the item and run `/stakes admin importitem <stake-id> <item-id>`. The plugin saves the item and updates the stake file; restart the server before the existing stake uses the imported snapshot.

`match-mode` controls custom-item matching: `SIMILAR` is the normal choice; `EXACT` requires a full match; `CUSTOM_MODEL_DATA` checks material and custom model data.

## Time and limits

All configured financial amounts must be at most `9,007,199,254,740,991`; larger values are rejected to keep database arithmetic and Vault conversions safe. A generated reward payload may use at most `60,000` UTF-8 bytes, configured commands have a `12,000`-byte encoded budget per reward block, and an imported custom-item snapshot at most `32 KiB` serialized binary. Commands must be non-null single lines and cannot contain the reserved U+0001 payload separator. Shorten command lists/item metadata or split a reward if validation reports these bounds.

Write durations as `30m`, `2h`, `1d`, or `1h30m`. Both `duration` and
`restart-delay` must be greater than zero.

| Setting | Meaning |
| --- | --- |
| `duration` | How long one round stays open. |
| `restart-delay` | Waiting time after a round ends. |
| `auto-restart` | `true` starts the next round after the delay; `false` waits for staff. |
| `min-invest` / `max-invest` | Minimum and maximum size of one deposit. |
| `daily-limit` | Player’s maximum net deposit for one server day; `0` means unlimited. |

`min-invest` and `max-invest` must both be positive, and the minimum cannot
exceed the maximum. When `daily-limit` is enabled, it must be at least
`min-invest`.

## Per-stake messages and reminders

Put lifecycle messages in the stake file, so every stake can use its own wording and styling:

```yaml
messages:
  started: "{prefix}<green>{stake} has been started."
  stopped: "{prefix}<green>{stake} has been stopped and finalized."
  reminder:
    interval: "5m"
    message: "{prefix}<gold>{stake}</gold> is active! Time left: <yellow>{time_left}</yellow>"
```

`started` and `stopped` are sent only to the administrator who runs the respective command.
`reminder.message` is broadcast at the configured interval while the round is active, but only to
online players who can access that stake. Leave `started`, `stopped`, or `reminder.message` empty to
disable that message. The reminder interval must be a positive duration such as `30s`, `5m`, or `1h`.

Available placeholders are `{stake}` (the display name), `{time_left}`, `{participants}`, and `{total}`.

## Alias and reward validation

Stake aliases are case-insensitive. Each non-empty alias must be unique and
cannot reuse a root listed in `config.yml` under `command.aliases` (or a
reserved server command such as `help` or `minecraft`). Use only letters,
digits, underscores, and hyphens; aliases are normalized to lowercase.

Keys below `prizes.top` must be unique positive ranks without gaps, starting
at `1`. For consolation rewards, `refund-percent` must be between `0` and
`100`; `amount` must be non-negative and is also limited to `100` when
`type: PERCENT`.

Rewards are documented only on the [Rewards](Rewards.md) page.

## Stake permission

`permission` is an optional root setting. When it is absent or empty, everyone who has the required
command and menu permissions can see and participate in the stake. When it contains a value, only
players with that exact permission can see or participate:

```yaml
permission: "stake.diamondrush"
```

The configured value is not prefixed or generated by UniversalStakes. Grant it through your
permissions plugin. See [Commands and Permissions](Commands-and-Permissions.md) for the complete
list of plugin command and menu nodes.
